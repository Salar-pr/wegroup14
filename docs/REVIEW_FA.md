# بررسی ادغام و نسخه نمایشی

مبنای بررسی: `origin/main` با شناسه `edf1409`. هر سه برنچ `feat/UH-02-admin-dashboard`، `feat/UH-03-student-dashboard` و `feat/UH-04-parent-dashboard` در تاریخچه `main` ادغام شده‌اند؛ merge مجدد لازم نبود. در سورس نشانه‌ای از conflict باقی نمانده بود. مشکل واقعی این بود که روتر `main` هنوز به جای پنل مدیر و دانش‌آموز صفحه موقت را نشان می‌داد.

در این نسخه هر سه پنل به روتر متصل شدند. دو فایل بلااستفاده `src/lib/axios.ts` و `src/lib/queryClient.ts` که بیلد را به خاطر وابستگی‌های نصب‌نشده خراب می‌کردند حذف شدند؛ پروژه همچنان بدون بک‌اند است. پیش‌نمایش قدیمی مدیر و گزارش‌های تحویل منسوخ هم کنار رفتند.

داده نمونه از ابتدا مشترک است: ۲۵ دانش‌آموز، ۱۰ خانواده، ۸ معلم، ۶ کلاس، ۳۹ نمره، ۳۶ رکورد حضور، ۱۳ صورت‌حساب و ۱۱ پیام. فرزند دوم خانواده محمدی از داده موقت مخصوص پنل اولیا به `src/data/` منتقل شد. حساب‌های بردیا (پیگیری تحصیلی)، فاطمه (شهریه معوق)، حسن (تسویه‌شده) و علی به سناریوهای ورود اضافه شدند. فهرست خانواده‌ها و پیام‌های مدیر هم به همین داده‌ها وصل شده‌اند.

## نتیجه بررسی

- `npm run build` موفق است؛ خطای TypeScript اولیه برطرف شد.
- `npm run lint` بدون خطا یا هشدار است.
- `npm run test:smoke`: ۱۸ بررسی اصلی از جمله صحت ارجاع داده‌ها، ورود سه نقش، کنترل دسترسی، مسیرها، پیام رفت‌وبرگشت، پاک شدن داده پس از refresh و نمای موبایل هر سه پنل موفق بود.
- تست مرورگر پنل اولیا: ۶۰ از ۶۰ مورد موفق، شامل دسکتاپ، تبلت، موبایل و تعاملات اصلی.
- `npm audit` هنوز هشدار وابستگی دارد (در زمان بررسی: ۲ مورد متوسط در وابستگی‌های زمان اجرا و ۲ مورد در ابزار توسعه). تغییر نسخه عمده React Router یا Vite بدون آزمون سازگاری انجام نشد.

## موارد باز و ایده‌های UI

1. پنل معلم و صفحه‌های حقوق، گزارش‌های پیشرفته و برنامه مدیر هنوز تکمیل نشده‌اند. بهتر است لینک‌های بخش‌های آماده‌نشده تا طراحی نهایی با برچسب «به‌زودی» مشخص یا پنهان شوند.
2. «معدل پرونده» در مدیریت مقدار جداگانه‌ای از «معدل نیم‌سال» محاسبه‌شده از نمره‌هاست. نام‌گذاری و راهنمای کنار این دو عدد باید تفاوتشان را برای کاربر روشن کند.
3. درخواست توجیه غیبت بهتر است در UI دو مرحله «در انتظار بررسی» و «تأیید شده» داشته باشد؛ اکنون برای نمایش تعامل، همان لحظه غیبت را موجه می‌کند.
4. برای نمایشگاه یا ارائه، یک کنترل کوچک «بازنشانی سناریو» و تاریخ‌های نمایشی شناور نسبت به روز اجرا کمک می‌کند تکالیف و مهلت‌ها در ماه‌های آینده قدیمی به نظر نرسند.

این‌ها پیشنهادهای رابط کاربری‌اند؛ هیچ‌کدام نیازمند بک‌اند در محدوده این پروژه نیستند.

## 📌 معرفی پروژه

**مدرسه‌یار (MadreseYar)** یک سامانه یکپارچه مدیریت مدرسه است که با هدف ساده‌سازی فرایندهای آموزشی، مدیریتی و ارتباطی میان مدرسه، دانش‌آموزان و والدین طراحی شده است.

این پروژه با رویکرد Multi-Panel توسعه داده می‌شود؛ به این معنا که هر گروه کاربری محیط اختصاصی و امکانات متناسب با نیازهای خود را در اختیار دارد.

هدف اصلی، ایجاد تجربه‌ای یکپارچه، ساده و قابل توسعه برای مدیریت امور آموزشی و اجرایی مدرسه است.

> **وضعیت پروژه:** نسخه فعلی بر توسعه Frontend تمرکز دارد. بک‌اند، پایگاه داده و احراز هویت واقعی در محدوده فعلی پروژه قرار ندارند.

## 🎯 اهداف پروژه

- یکپارچه‌سازی فرایندهای مدیریتی و آموزشی مدرسه
- تسهیل ارتباط میان مدرسه، دانش‌آموز و والدین
- دسترسی سریع به اطلاعات تحصیلی و آموزشی
- بهبود مدیریت کلاس‌ها و برنامه‌های درسی
- نمایش شفاف وضعیت تحصیلی دانش‌آموزان
- کاهش فرایندهای تکراری و پراکندگی اطلاعات
- طراحی رابط کاربری مدرن، واکنش‌گرا و فارسی

## 👥 پنل‌های سامانه

### 1. پنل مدیریت مدرسه (Administration Panel)

این پنل برای مدیران و مسئولان مدرسه طراحی شده است.

قابلیت‌های هدف:

- داشبورد مدیریتی
- مدیریت دانش‌آموزان
- مدیریت معلمان و کارکنان
- مدیریت کلاس‌ها و پایه‌های تحصیلی
- مدیریت دروس
- برنامه‌ریزی کلاس‌ها
- مدیریت حضور و غیاب
- مدیریت نمرات و کارنامه‌ها
- انتشار اطلاعیه‌ها
- گزارش‌گیری و مشاهده آمار مدرسه

### 2. پنل دانش‌آموز (Student Panel)

این پنل محیط اختصاصی دانش‌آموز برای پیگیری فعالیت‌های آموزشی است.

قابلیت‌های هدف:

- داشبورد شخصی
- مشاهده برنامه هفتگی
- مشاهده دروس و معلمان
- مشاهده نمرات
- مشاهده وضعیت تحصیلی
- پیگیری تکالیف
- مشاهده وضعیت حضور و غیاب
- دریافت اطلاعیه‌های مدرسه
- مدیریت اطلاعات پروفایل

### 3. پنل والدین (Parent Panel)

این پنل برای ارتباط والدین با مدرسه و پیگیری وضعیت تحصیلی فرزندان طراحی شده است.

قابلیت‌های هدف:

- داشبورد وضعیت تحصیلی فرزند
- مشاهده نمرات و عملکرد آموزشی
- بررسی وضعیت حضور و غیاب
- مشاهده برنامه هفتگی
- پیگیری تکالیف
- دریافت اطلاعیه‌ها
- دسترسی به اطلاعات آموزشی فرزند

> قابلیت‌های فوق نقشه کلی محصول هستند و درج آن‌ها در این بخش به معنی پیاده‌سازی کامل تمام موارد نیست.

## 🔬 تحقیق و توسعه (R&D)

در این پروژه، R&D یا Research & Development به معنای تحقیق، تحلیل، طراحی و ارزیابی راهکارهای مناسب پیش از توسعه و پیاده‌سازی قابلیت‌ها است.

### مراحل R&D

1. **Research:** بررسی نیازهای کاربران، تحلیل نمونه‌های مشابه و جمع‌آوری اطلاعات.
2. **Analysis:** تحلیل نیازمندی‌ها، شناسایی مشکلات و تعریف سناریوهای کاربری.
3. **Design:** طراحی رابط کاربری، معماری اطلاعات و تجربه کاربری.
4. **Development:** پیاده‌سازی قابلیت‌ها با استفاده از تکنولوژی‌های انتخاب‌شده.
5. **Validation:** ارزیابی عملکرد، تست رابط کاربری و بررسی صحت پیاده‌سازی.
6. **Iteration:** اصلاح و بهبود مستمر بر اساس بازخورد کاربران و نتایج تست.

### اصول تحقیق و توسعه

- بررسی راهکارهای موجود پیش از انتخاب تکنولوژی
- تحلیل نیازهای واقعی هر گروه کاربری
- بررسی تجربه کاربری و دسترس‌پذیری
- انتخاب ابزارهای مناسب بر اساس نیاز پروژه
- جلوگیری از پیچیدگی غیرضروری در معماری
- ثبت تصمیمات فنی و دلایل انتخاب آن‌ها
- ارزیابی مستمر کیفیت و عملکرد محصول

## 🚀 راه‌اندازی محلی

### مرحله اول: دریافت پروژه

```bash
git clone https://github.com/Salar-pr/wegroup14.git
```

### مرحله دوم: ورود به پوشه پروژه

```bash
cd wegroup14
```

### مرحله سوم: نصب وابستگی‌ها

```bash
npm install
```

در صورت وجود `package-lock.json` می‌توانید از دستور زیر برای نصب نسخه‌های قفل‌شده استفاده کنید:

```bash
npm ci
```

### مرحله چهارم: تنظیم متغیرهای محیطی

در صورت نیاز فایل نمونه را کپی کنید.

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

نمونه متغیر:

```env
VITE_APP_NAME=Madreseyar
```

### مرحله پنجم: اجرای پروژه

```bash
npm run dev
```

پس از اجرای موفق، آدرس محلی در ترمینال نمایش داده می‌شود.

آدرس پیش‌فرض Vite:

```text
http://localhost:5173
```

### مرحله ششم: ساخت نسخه Production

```bash
npm run build
```

### مرحله هفتم: پیش‌نمایش نسخه Production

```bash
npm run preview
```

## ⚙️ متغیرهای محیطی

در حال حاضر متغیر نمونه زیر در پروژه در نظر گرفته شده است:

| متغیر | توضیحات | الزامی |
|---|---|---|
| `VITE_APP_NAME` | نام نمایشی برنامه | خیر |

نمونه:

```env
VITE_APP_NAME=Madreseyar
```

**نکات امنیتی:**

- متغیرهای دارای پیشوند `VITE_` در محیط مرورگر قابل دسترسی هستند.
- اطلاعات محرمانه را در این متغیرها قرار ندهید.
- فایل `.env` نباید در Git Commit شود.
- فقط فایل `.env.example` بدون اطلاعات محرمانه در مخزن نگهداری شود.

## 🌿 استانداردهای Git

### نام‌گذاری Branch

| Prefix | کاربرد | نمونه |
|---|---|---|
| `feat/` | قابلیت جدید | `feat/student-dashboard` |
| `fix/` | رفع باگ | `fix/sidebar-responsive` |
| `docs/` | مستندات | `docs/update-readme` |
| `refactor/` | بازآرایی کد | `refactor/shared-layout` |
| `style/` | تغییرات ظاهری | `style/dashboard-cards` |
| `chore/` | امور نگهداری و تنظیمات | `chore/update-dependencies` |
| `test/` | تست | `test/student-panel` |

### گردش کار پیشنهادی

```bash
git switch main
git pull origin main

git switch -c feat/student-dashboard

git add .
git commit -m "feat: implement student dashboard"

git push -u origin feat/student-dashboard
```

### استاندارد Commit

از الگوی Conventional Commits استفاده کنید:

```text
feat: add parent dashboard
fix: correct mobile navigation
docs: update project README
refactor: extract shared components
style: improve dashboard layout
test: add navigation smoke test
chore: update dependencies
```

### کاهش Merge Conflict

- محدوده کاری اعضای تیم از ابتدا مشخص شود.
- هر عضو در Branch مستقل کار کند.
- فایل‌های مشترک بدون هماهنگی تغییر نکنند.
- قراردادهای مشترک پیش از شروع توسعه مشخص شوند.
- تغییرات کوچک و مستقل در Pull Request ارسال شوند.
- پیش از Merge، آخرین تغییرات شاخه مقصد دریافت شوند.
